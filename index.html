PDF → Excel

Converts supplier PDFs (scanned, digital or mixed) into structured Excel workbooks. Supplier order reports are read from the document's own column layout, and every row that cannot be read is reported rather than dropped.

Capabilities

Everything you need

Handles every PDF type with intelligent extraction — no manual configuration required.

All PDF Types

Native text, scanned image-based, and mixed-content PDFs. Auto-detected per page — no manual flag needed.

text · scanned · mixed

Smart Table Detection

Cascades through three extraction engines automatically: pdfplumber first, then camelot, then tabula as fallback.

OCR Support

Scanned pages rendered at 300 DPI, enhanced with Pillow contrast/sharpening, then passed through Tesseract OCR with confidence filtering.

tesseract · multi-language

Batch Processing

Usage

From quick one-liners to full batch processing pipelines.

bash
# Basic — output auto-saved to ./output/
python pdf_to_excel.py invoice.pdf
bash
# Custom output path
python pdf_to_excel.py report.pdf -o results/report_2024.xlsx
bash
# Preview tables before saving
python pdf_to_excel.py report.pdf --preview
bash
# Force specific extraction method
python pdf_to_excel.py tricky.pdf --method camelot
bash
# OCR in French
python pdf_to_excel.py french_doc.pdf --ocr-lang fra
bash
# Process all PDFs in a folder
python pdf_to_excel.py -d ./pdfs/ -o ./output/
bash
# Batch with table preview
python pdf_to_excel.py -d ./invoices/ -o ./results/ --preview
Batch mode generates a _batch_summary_TIMESTAMP.xlsx in the output folder with success/fail counts, durations, and error details for every file.

# CSV with custom output folder
python pdf_to_excel.py data.pdf --format csv -o ./csv_output/
Each table becomes a separate CSV: filename_P1_T1.csv, filename_P1_T2.csv, etc.

Order Reports

Order Reports

The tool reads the supplier order report from its physical column layout rather than by pattern-matching text. It activates automatically — no flag required — when a page contains the report header.

detected header
S. No. Customer Name Item Product Type Certificate No Order No Amount Manufacturer Est Shipping Date

For each page the parser locates the header, then calibrates where each column begins by finding the widest empty vertical strip between adjacent labels — headers are centred over their columns while the data beneath is left-aligned, so a naive midpoint lands inside real values. Every word is then assigned to the column it is physically printed under. A value's column is a fact recorded in the file; its shape is only a guess.

Wrapped Cells

A cell continuing on the next line is appended under its own column. Bellamy Double Halo + Engagement Ring become one Item; IGI + LG_100000003 one Certificate No.

multi-line rows

Blank Cells

A setting or mounting has no certificate. The column is simply empty — no pattern has to account for a missing field, and the row is kept.

no false rejections

Any Product Type

Diamond, Setting, or anything new. Product type is read from its column and never required to be a particular word.

no fixed row shape

Forces Column Types

Order No and Certificate No stay text so Excel cannot reformat them as numbers or dates. Amount becomes real currency.

no silent reformatting
Rows that fail validation are excluded from the output Each row must carry the fields that make it a usable financial record: a numeric serial number, an Amount, an Order No, and a DD Mon YYYY date. Certificate No and Product Type are deliberately not required — settings and mountings legitimately have neither.

Exclusions are never silent — each one is reported as a console warning, logged in full under logs/, counted as Unparsed Report Rows in the _Metadata sheet, and shown in an amber Unparsed Rows column in the batch summary.

If that count is not zero, reconcile before using the data. Every report states its own totals in the header (25 Items - $5970.06); checking the extracted row count and the sum of Amount against that line is the fastest way to confirm a run is complete.
Troubleshooting

Common Issues

Most problems are missing system dependencies. Run --check-deps first.

Some rows were left out of the Excel file. Do not treat the output as complete until you have checked them.

1. Open the newest file in logs/ and search for Unparsed report row — each excluded row is logged in full.
2. Check it against the four required fields in Order Reports: serial number, Amount, Order No, and a DD Mon YYYY date.
3. Reconcile the run against the report's own N Items - $X header line to see exactly what is missing.

Usual causes: a missing or reformatted amount or date, a serial number that did not extract cleanly, or a page whose column layout could not be read — in which case the stricter text fallback was used.

A product type other than Diamond, or a blank certificate, is not a cause — those are handled normally by the column parser. If the report's columns have genuinely been rearranged, ReportColumnParser needs updating; that is a code change, not a config one.
Try forcing a different extraction method:
python pdf_to_excel.py file.pdf --method camelot
python pdf_to_excel.py file.pdf --method tabula

If it's a scanned PDF, ensure Tesseract is installed and on PATH. Some PDFs use non-standard encoding — try opening in a PDF viewer first to confirm tables are visually present. Check logs/ with --verbose for detailed extraction attempts.
Verify Tesseract is installed:
tesseract --version

Windows fix — set path in config.json:
"tesseract_path": "C:/Program Files/Tesseract-OCR/tesseract.exe"

Download from: UB-Mannheim Tesseract Wiki
Camelot is optional — it only ships if you install requirements-optional.txt, and the tool works fully without it. Seeing camelot-py: NO in --check-deps is expected otherwise.

If you did install it, Camelot also requires Ghostscript for PDF rendering. Check:
gswin64c --version (Windows 64-bit)
gs --version (macOS/Linux)

Download: ghostscript.com

If you don't need camelot, use --method pdfplumber to skip it entirely.
Tabula is optional — it only ships if you install requirements-optional.txt. Seeing tabula-py: NO in --check-deps is expected otherwise.

If you did install it, tabula-py needs Java 8 or newer. Check:
java -version

If missing, install from java.com.
To skip tabula entirely and use only pdfplumber:
python pdf_to_excel.py file.pdf --method pdfplumber
Performance tips:
• Reduce OCR DPI in config: "ocr_dpi": 150
• Skip slow fallback engines: --method pdfplumber
• For text-only PDFs, pdfplumber is fastest by far.
• For batch jobs, OCR-heavy runs: use overnight processing or split the folder into chunks.
Corrupted PDFs: the script logs the error and continues (batch mode skips them). To repair:
qpdf --linearize corrupted.pdf fixed.pdf

Password-protected PDFs are not supported directly. Remove the password first using a PDF editor or qpdf --password=YOURPASS --decrypt locked.pdf unlocked.pdf.
